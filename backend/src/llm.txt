# Music Server API — LLM Reference

> Machine-readable documentation for AI assistants and LLM-based tooling.
> Base URL: /api
> Authentication: Bearer token in the Authorization header, or ?token= query param for SSE.
> All authenticated endpoints accept: JWT (Google SSO), static ADMIN_TOKEN, static API_TOKEN,
> or a user-generated personal access token (prefix: ms_).

---

## Authentication

### Token Types

| Type | Prefix | Source | Admin | Permissions |
|------|--------|--------|-------|-------------|
| JWT | (none) | Google SSO login | per user | full access |
| Admin token | (none) | ADMIN_TOKEN_SHA256 env var | yes | full access |
| API token | (none) | API_TOKEN_SHA256 env var | no | full access |
| Personal access token | ms_ | Created via /api/tokens | no | configurable |

### Personal Access Token Permissions

Each personal access token carries four boolean flags:
- can_read   — GET requests: stream music, browse library, playlists, artists, genres
- can_create — POST requests: upload tracks, create playlists, add streams
- can_edit   — PATCH/PUT requests: update metadata, rename, reorder
- can_delete — DELETE requests: remove tracks, playlists, streams

Tokens can optionally have an expires_at timestamp. Expired tokens return 401.
Token management (CRUD on /api/tokens) requires full JWT authentication — personal access tokens cannot manage other tokens.

### Personal Access Tokens

GET /api/tokens
  Auth: JWT required
  Description: List all personal access tokens for the current user.
  Response: Array of TokenInfo (see schema below)

POST /api/tokens
  Auth: JWT required
  Body: {
    "name": "string (required, max 255 chars)",
    "can_read": true,
    "can_create": false,
    "can_edit": false,
    "can_delete": false,
    "expires_at": "2026-12-31T00:00:00Z" | null
  }
  Description: Create a new personal access token. The plaintext token is returned ONCE.
  Response: {
    "token": "ms_<64 hex chars>",
    "info": TokenInfo
  }

GET /api/tokens/:id
  Auth: JWT required
  Description: Get metadata for a specific token owned by the current user.
  Response: TokenInfo

PATCH /api/tokens/:id
  Auth: JWT required
  Body: {
    "name": "string (optional)",
    "can_read": bool (optional),
    "can_create": bool (optional),
    "can_edit": bool (optional),
    "can_delete": bool (optional),
    "expires_at": "ISO 8601 datetime (optional)",
    "clear_expires_at": bool (optional, set true to remove expiry)
  }
  Description: Update a token's name, permissions, or expiry.
  Response: TokenInfo

DELETE /api/tokens/:id
  Auth: JWT required
  Description: Permanently revoke and delete a token.
  Response: 204 No Content

TokenInfo schema:
  {
    "id": "uuid",
    "name": "string",
    "can_read": bool,
    "can_create": bool,
    "can_edit": bool,
    "can_delete": bool,
    "last_used_at": "datetime | null",
    "expires_at": "datetime | null",
    "created_at": "datetime"
  }

### Music Files

GET /api/music
  Auth: required
  Query params: search, genre, artist, sort, order, limit, offset, unconfirmed_only, missing_metadata
  Description: List music files with filtering and pagination.
  Response: Array of MusicFile

  Auth: required
  Description: Return all tracks from the in-memory cache (fast).
  Response: Array of MusicFile

GET /api/music/stats
  Auth: required
  Query params: search, genre, artist, unconfirmed_only, missing_metadata
  Response: { "total": int }

POST /api/music
  Auth: required, can_create
  Body: { "title", "artist"?, "album"?, "duration"?, "file_path" }
  Description: Create a music file record.

GET /api/music/:id
  Auth: required
  Response: MusicFile (full detail)

PATCH /api/music/:id
  Auth: required, can_edit
  Body: Partial MusicFile fields
  Description: Update track metadata.

DELETE /api/music/:id
  Auth: required, can_delete
  Description: Remove track and its file.

POST /api/music/upload
  Auth: required, can_create
  Body: multipart/form-data with file(s)
  Description: Upload one or more audio files.

POST /api/music/sync
  Auth: required, can_create
  Body: { "folder"?: "string" }
  Description: Sync the music folder (scan for new/removed files).

POST /api/music/:id/bpm-detect
  Auth: required, can_edit
  Description: Detect and store BPM for a track.

POST /api/music/:id/cut
  Auth: required, can_edit
  Body: { "start": float, "end": float }
  Description: Trim a track to the given time range (seconds).

GET /api/music/:id/stream
  Auth: required (query param ?token= supported for HTML5 audio)
  Description: Stream the audio file (supports HTTP Range).

GET /api/music/:id/playlists
  Auth: required
  Description: List playlists that contain this track.

POST /api/music/release-date-lookup
  Auth: required
  Body: { "title": "string", "artist"?: "string" }
  Description: Look up release date via configured metadata source.

GET /api/music/metadata-suggestions
  Auth: required
  Query: limit, offset
  Description: List pending metadata suggestions from background analysis.

DELETE /api/music/metadata-suggestions/:id
  Auth: required, can_delete
  Description: Dismiss a metadata suggestion.

DELETE /api/music/metadata-suggestions
  Auth: required, can_delete
  Description: Dismiss all pending metadata suggestions.

POST /api/music/check-duplicate
  Auth: required
  Body: { "hash": "string" }
  Description: Check whether a file with the given SHA-256 hash already exists.

MusicFile schema (subset):
  {
    "id": "uuid",
    "title": "string",
    "artist": "string | null",
    "album": "string | null",
    "genre": "string | null",
    "guessed_genre": "string | null",
    "duration": int (seconds),
    "release_date": "datetime | null",
    "bpm": float | null,
    "initial_key": "string | null",
    "file_path": "string",
    "file_hash": "string | null",
    "metadata_analyzed": bool,
    "created_at": "datetime",
    "updated_at": "datetime"
  }

## Error Format

All errors follow:
  { "error": "error_code", "message": "Human readable description" }

Common HTTP status codes:
  200 OK            — success with body
  201 Created       — resource created
  204 No Content    — success, no body (e.g. DELETE)
  400 Bad Request   — invalid input
  401 Unauthorized  — missing or invalid token
  403 Forbidden     — authenticated but insufficient permissions
  404 Not Found     — resource does not exist
  422 Unprocessable — validation error
  500 Internal      — server error

## SSE (Server-Sent Events) Usage

Endpoints ending in /stream return an SSE stream. Browsers cannot set Authorization headers
for EventSource, so pass the token as a query parameter:

  const source = new EventSource('/api/music/sync/stream/SESSION_ID?token=YOUR_TOKEN')
  source.onmessage = (event) => {
    const data = JSON.parse(event.data)
    console.log(data)
  }

## Personal Access Token Quick Start

1. Log in with Google SSO to obtain a JWT.
2. POST /api/tokens with the desired permissions and a human-readable name.
3. Copy the returned token value (shown once only).
4. Use the token in subsequent requests:
   Authorization: Bearer ms_<your token>

Example (curl):
  TOKEN=$(curl -s -X POST /api/tokens \
    -H "Authorization: Bearer <JWT>" \
    -H "Content-Type: application/json" \
    -d '{"name":"curl client","can_read":true}' \
    | jq -r .token)

  curl /api/music -H "Authorization: Bearer $TOKEN"
